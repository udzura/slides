# Fukuoka Wasm #1

ソースコードのサンプルを、行単位でホバーできるインラインSVGに変換する。
対象はコードフェンスの言語が `c`・`cpp`・`js`・`wat` のもの（現在8ブロック）。
コマンド例（`sh`）・出力例（`text`）・言語指定のないブロックは通常の `pre` のまま残す。
コードは `index.md` の通常のコードフェンスで編集する。

```sh
python3 fukuokawasm-1/build.py
```

リポジトリルートから実行する場合のコマンド。ビルドスクリプトは他の作業ディレクトリからでも実行可能。
MarpでHTML生成後、対象のソースコードだけ変換し、C・C++・JSの構文の色分けも維持する。
WATは簡易的な色分けを追加する：`;;` 以降の行コメントはグレー、数値・文字列は緑、`$` で始まる変数・ラベル・タグ名は青。
文字列内の `;;` や `$` は文字列として扱い、命令名の `i32` などに含まれる数字は色分けしない。
コードフェンスの対象数と実際の変換数が一致しなければビルドを失敗させる。
通常の `marp` コマンドだけで再生成するとSVGへの変換は含まれない。

OGPは1枚目を1920×1080のPNGに書き出した `ogp.png`。Markdownの `image` には公開先の `https://udzura.jp/slides/2026/fukuokawasm-1/ogp.png` を設定している。
タイトルスライドを変更した場合は、このディレクトリで次を実行して画像も更新する。

```sh
marp --no-stdin index.md --image png --image-scale 1.5 --allow-local-files -o ogp.png
```

行の横幅全体がホバー対象。対象行は明るい背景（#fffdf9）と朱色のマーカー、他行は濃い背景（#d3d5c9）。文字の不透明度は変えない。
ホバー中は枠の上下の余白も同じ濃い背景にする。切り替えは120ms。行から離れると全行を通常表示する。
印刷では全行を通常表示し、動きを減らす設定ではtransitionを無効にする。

プレビュー: http://127.0.0.1:8767/fukuokawasm-1/#11

6枚目の `trap`、8枚目の定義行の `exnref`、11枚目の「（参考: 旧方式との違い）」、19枚目の「捕捉する」には補足説明のポップアップを付けている。マウスオーバーまたはTabによるフォーカスで180msかけて表示する。
共通の `.term-help` スタイルを使い、`exnref` は左揃え・下方向に開いてスライドの左端からはみ出さないようにする。
ポップアップへポインタを移しても表示を保ち、用語と説明の両方から離れると閉じる。印刷時は非表示にし、動きを減らす設定ではアニメーションを無効にする。

「CとWasmの対応」（23・24枚目）は、同じCコードを左に置いた2枚のSVG図。
`draw-sjlj.py` でコードと対応する処理・強調箇所を編集し、`python3 fukuokawasm-1/draw-sjlj.py` で `images/sjlj-flow.svg` と `images/sjlj-return.svg` を生成する。
通常のHTML再ビルドでは保存済みSVGを使うため、`draw-sjlj.py` を変更したときだけ先に再生成する。
ビルドスクリプトが2枚をインライン化し、HTML内で各要素のホバーが動くようにする。
1枚目は初回の0とcase 0、2枚目はthrowと捕捉後のcase 42を強調する。
ホバーすると対応するCの行とWasm側の処理を同時に強調する。他の要素は濃い背景になり、文字の濃さは維持する。
Tabで図の各要素へ移動した場合も強調する。印刷時は通常表示に戻し、動きを減らす設定に対応する。
通常のMarpだけで生成した場合も図は画像として表示されるが、要素単位のホバーはビルドスクリプト経由で有効になる。
